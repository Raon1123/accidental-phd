# 디자인 실험 (A/B)

화면 디자인을 한 번에 확정하지 않고, 변형을 나란히 두고 보고 반응을 기록해 쌓는다. 코드 결정은 [결정 기록](../decisions/README.md)이, 실험의 근거와 반응은 여기가 맡는다.

## 디자인 큐
디자인 요청은 issue(`[design]` 접두, `area/ui`)로 등록하고 issue 번호 순(FIFO)으로 한 번에 하나씩 처리한다. 한 issue는 PR 하나이고, 앞 issue를 끝내기 전에 다음으로 넘어가지 않는다. 새 요청은 큐 맨 뒤에 붙는다. 큐 상태는 이 폴더의 실험 기록과 issue 댓글에 남기고 채팅에는 남기지 않는다.

## 변형 켜기
- `web/src/variant.ts`의 `EXPERIMENTS`에 실험 이름과 변형 목록을 둔다. 첫 항목이 기준(a).
- URL에 `?layout=b`처럼 쓰면 `<html data-layout="b">`가 되고, `style.css`의 `html[data-layout="b"]` 규칙이 켜진다. 같은 브라우저에서는 선택이 남는다.
- `?ab=1`을 더하면 오른쪽 아래에 전환 막대가 뜬다.
- 변형 규칙은 기준 규칙을 고치지 않고 `style.css` 맨 아래에 덧붙인다. 실험이 끝나면 이긴 변형을 기준으로 합치고 나머지 규칙과 목록 항목을 지운다.

## 지킬 것
- `web/test/a11y.test.ts`가 보는 색 토큰(`:root` 첫 블록과 다크 블록)은 변형에서 바꾸지 않는다. 새 색이 필요하면 토큰을 먼저 추가하고 대비 검사를 통과시킨다.
- `index.html`에 한글을 넣지 않는다(결정 기록 0001). 글 문구는 `strings.ko.ts`(#57 담당)에 있으므로 변형은 CSS만 바꾼다.
- 실제 학교명을 화면에 내지 않는다(0004).

## 한 실험의 기록
파일 하나(`NNNN-<slug>.md`)에 다음을 적고, 반응이 올 때마다 `## 반응`에 날짜와 함께 덧붙인다(지우지 않는다).

```markdown
# NNNN. <제목>
## 가설
<무엇이 어떻게 나아질 것이라 보나>
## 변형
<a/b/c 가 각각 무엇인가>
## 측정
<자동으로 잰 값(스크립트·명령)과 사람이 보는 항목>
## 반응
- YYYY-MM-DD <누가> <무엇을 봤고 무엇이라 했나>
## 결정
<진행 중 | 채택: x | 폐기> · <날짜>
```
