# 무작위 문장 팩 브레인스토밍과 가상 기관명 후보 (#112, 2026-10-14)

사용자 요청(2026-10-14): 원작 v3.5 페이지의 무작위 이야기처럼 그 달 상황에 맞는 짧은 문장을 연구노트에 넣는다. 문장은 Haiku 여러 개가 쓰고, seed 프롬프트만 workflow에서 다듬는다. 이 문서는 설계 브레인스토밍이고, 팩 파일과 화면 연결은 이 문서 승인 뒤 후속 PR에서 한다.

- 결정 기록 0002: 원작 문장은 복사하지 않는다. 구조만 관찰했다.
- 결정 기록 0004: 화면에는 실제 기관 이름을 쓰지 않는다. 이 문서도 실제 기관 이름을 적지 않는다. 기관은 `inst-NN` 키로만 가리키고, 실제 이름과의 대응표는 저장소 밖 비공개 파일에 둔다(#113의 결정: 실명은 비공개 대응표로 분리).
- 작성 과정: 정찰(Sonnet) → seed 프롬프트(Opus) → 범주별 문장·기관명 작성(Haiku 5개) → 감사(Fable, `docs/prompts/judge-any.md`). 아래 문장은 감사 판정(keep·revise)을 반영한 결과다.

## 1. 원작 구조 관찰

정찰 에이전트가 원작의 이야기 모듈을 읽고 자기 말로 정리한 내용이다(문장 인용 없음).

- 장면은 네 종류의 생성 도우미로 만든다: 박사과정(최소 4개월째, 재등장 간격 30개월), 경력(간격 48개월), 은퇴(간격 48개월), 생활(세 단계 공통, 최소 3개월째, 간격 48개월).
- 장면마다 짧은 태그, 제목, 본문, 숨은 결과 목록이 있다. 결과는 가중치와 능력치·자원 효과, 후속 장면 예약을 가진다.
- 묶음: 박사과정 일반 약 16개, 분야(6개)마다 3개(분야가 맞으면 가중치 2), 연구 트랙마다 생성 장면 하나, 생활 약 10개, 경력 약 16개, 은퇴 8개, 후속 전용 9개.
- 조건: 단계가 맞을 것, 최소 개월 수, 휴학·휴식 중에는 연구 장면 제외, 분야·트랙 필터, 후속 장면의 선행 플래그, 추가 조건(논문 게재, 재직 등). 한 번만 나오는 장면과 간격 뒤 재등장 장면이 있다.
- 선택: 예약된 후속 장면이 먼저다. 아니면 가중치 / (1 + 2 × 최근 4개 이야기 중 같은 태그 수)로 가중 추첨한다. 같은 태그가 연달아 나오는 것을 줄인다. 추첨은 저장된 seed로 결정적이다.
- 빈도는 고정 월 확률이 아니라 재등장 간격, 최소 개월 수, 태그 반복 감쇠로 정해진다. 원작에서 추첨을 부르는 시점(매달인지 특정 사건인지)은 이 모듈만으로는 보이지 않았다.

우리 엔진에는 선택지 장면이 없다(결정 기록 0005의 선택권은 결정점으로 따로 있다). 그래서 이식 방향은 **선택지 없는 한 줄 메모**다. `web/src/play.ts`의 `notes()`가 이미 기록 뒤에 `logScene` 문장을 `creative: true, scene: true`로 붙이므로, 무작위 문장도 같은 자리에 붙인다.

## 3. 빈도와 선택 규칙(제안)

- 한 달에 최대 한 줄. 그 달에 결정 결과 문장이나 `logScene` 장면 문장이 이미 붙었으면 무작위 문장은 붙이지 않는다.
- 후보는 범주 조건과 태그로 거른다. 태그에 분야(인류학·민속학·종교학·수학 등)가 있는 줄은 플레이어의 트랙 분야가 맞을 때만 나온다. 분야 태그가 없는 줄(가족, 행정 등)은 모든 분야에 나온다.
- 같은 줄의 재등장 간격: 박사과정 30개월, 그 밖 48개월(원작 구조와 같은 값, 구현 때 0014에 가정 상수로 올린다).
- 가중치 = 1 / (1 + 2 × 최근 4줄 중 같은 첫 태그 수).
- 추첨은 화면 쪽에서 별도 seed(저장 seed + `flavor`)로 한다. 엔진 상태 추첨과 섞지 않아서 문장 팩이 바뀌어도 게임 결과가 바뀌지 않는다.
- 나오는 비율 목표: 박사과정 기간 중 대략 서너 달에 한 줄. 첫 구현 뒤 화면 기록 샘플로 확인한다.

## 4. 창작 표시

모든 줄은 `creative: true`로 붙고, 화면은 기존 장면 문장과 같은 "창작" 표시를 단다. 숫자·금액·확률은 문장에 넣지 않는다(숫자는 게임이 따로 보여준다). 실제 인물·학교·회사·기관·사업 이름도 넣지 않는다.

## 5. 엔진과 화면 연결 방안(후속 PR)

- 팩 파일: `data/text/flavor.ko.json` — `{ id, category, text, tags[] }` 배열. 형식 검사는 `scripts/validate-data.mjs`에 추가(길이 15~45자, 숫자 없음, 범주·태그 필수).
- 선택 함수: `web/src/flavor.ts`의 `flavorLine(state, entry, recent)` — DOM 없는 순수 함수. `notes()`가 기록마다 부르고, 3절 규칙으로 고른다.
- 테스트: 같은 seed면 같은 줄, 분야 필터, 재등장 간격, 태그 감쇠, 장면 문장이 있는 달에는 생략, 실명 목록(비공개 대응표의 해시, #113)과 겹침 0건.
- 엔진은 바꾸지 않는다. 문장 팩이 늘어도 보정 결과는 그대로다.

4. 실존 인물, 학교, 회사, 기관, 정부 사업 이름 금지. (예: 어떤 대학 이름, 연구원 이름, 재단 이름, 지원사업 이름 모두 금지.) 역할로만 쓴다: 지도교수, 동기, 선배, 후배, 행정실, 심사위원, 팀장, 가족.
5. 어떤 분야나 진로도 깎아내리거나 놀리지 않는다.
6. 사실을 주장하는 문장 금지(통계, 제도 설명, "보통 ~한다" 같은 일반화). 한 사람이 겪은 장면만 쓴다.
7. 게임 상태와 모순 금지: 취업·합격·임용을 약속하지 않는다, 결과(게재 확정, 학위 취득 등)를 기록보다 앞서 단정하지 않는다, 범주 조건에 없는 단계(예: 박사과정 중인데 졸업 후 이야기)를 쓰지 않는다.
8. 다른 게임이나 기존 작품의 문장을 베끼거나 바꿔 쓰지 않는다. 직접 새로 쓴다.
9. 24개 문장끼리 첫 두 어절이 겹치지 않게 한다.

- {"text":"동네 빵집 사장이 새 오븐 설명서를 끝까지 읽었다.","tags":["가게","준비"]}
- {"text":"등산 동호회 총무가 다음 달 코스를 지도에 표시해 두었다.","tags":["동호회","계획"]}

## tags 규칙
- 각 줄에 1~3개. 짧은 한국어 명사.
- 첫 태그는 하위 상황 이름(예: 진로 이름, 집중 활동, 사람 종류, 분야)으로 쓴다. 같은 하위 상황이면 같은 표기를 쓴다.
