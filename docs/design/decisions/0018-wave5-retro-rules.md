## 맥락
약어는 [용어집](../../workflow.md#용어집)을 따른다. 스펙 세 편은 Wave 3 회고와 같이 상태 스펙, 선택권 스펙, 노동 스펙이라 부른다. 이 기록은 [Wave 5 회고](../../waves/wave-05-ui-narrative.md) §결정 기록으로 올릴 것 4건을 결정으로 바꾼다. 형식은 결정 기록 0015·0016을 따른다. 학교·기관·학술지·학회는 실명 대신 id나 가상 표시명으로 적는다.

1. **플레이어 선택 범위.** 결정 기록 0005는 입학 전 선택 6종(계열 → 전공군 → 세부전공 → 학교·학과 → 자금 경로 → 지도교수 유형 선호)과 각 단계의 "운에 맡기기"를 정했다. Wave 5에서 사용자는 세 번 범위를 줄였다. (a) 2026-10-14: 입학 전에는 분야(전공군) 하나만 고르거나 분야도 운에 맡긴다(#54, PR #66). (b) 2026-10-14: 학교 선택 화면을 만들지 않는다. 학교는 운이고 플레이어는 분야만 고른다(#69 취소; 구현 커밋을 PR #74에서 되돌림, 6252a8c·7a63b34). (c) 2026-10-15: 박사과정의 과제 참여율은 플레이어가 고르지 않고, 학기마다 연구 일자리 수요와 교수 관계에 비례하는 난수로 정한다(PR #117, 0014 #130, 선택권 §4.7). 0005 본문은 바뀌지 않아 6종 선택이 여전히 정본처럼 읽힌다.
2. **실명 금지 범위.** 0004는 "데이터 팩은 실명과 공식 출처로 기록하고 화면만 가상 표시명"으로 정했다. 사용자는 2026-10-14에 issue #113으로 이를 넓혔다: 실제 기관명(학교, 연구기관, 지원 기관, 정부 사업)을 git 기록까지 포함해 저장소에서 지운다. 실명과 출처 URL은 저장소 밖 비공개 대응표에 두고, 누출 테스트는 실명의 해시로 돈다. 실행은 Wave 5 뒤로 보류했고, 그때까지 새로 쓰는 issue·PR·커밋 메시지·문서·데이터는 id나 가상명을 쓴다. 2026-10-15에는 학술지·학회 이름도 실명에 넣었고, 화면은 투고처를 `Q1~Q4 학술지·학회`로 보인다(PR #118).
3. **기록 다시 쓰기와 커밋 해시 인용.** #113 절차 5단계는 `git filter-repo`로 모든 커밋의 파일 내용과 메시지를 바꾼다. 이렇게 하면 모든 커밋 해시가 바뀐다. 결정 기록 0016 §1은 wave 체크리스트·결정 기록·보정 결과표가 커밋 해시를 완료 근거와 옛 값 검색 기준점으로 인용하므로 병합 커밋만 쓰기로 했다. Wave 5 체크리스트만 해시 22개를 인용한다. 다시 쓴 뒤 이 인용은 main에서 찾을 수 없게 된다. #113의 보류 조건("Wave 5 뒤")은 이 회고로 충족된다.
4. **병렬 세션의 공유 파일 책임.** Wave 5는 여러 세션(엔진·데이터 세션, design 세션, 참여율 세션 등)이 2026-10-14(UTC) 하루에 PR 35건(#62~#128)을 머지했다. 두 공유 파일이 갱신되지 않았다. (a) `scripts/check-assumed.mjs`의 `MAX = 121`은 0014 #122~#130이 더해진 뒤에도 그대로라 HEAD에서 exit 1이다(처음 커밋 289cf24). CI는 이 스크립트를 돌리지 않는다. (b) `docs/workflow.md` §브랜치·PR 규약은 머지한 PR이 STATUS를 같은 PR에서 갱신하게 하지만, 2026-10-14 10:47Z 뒤 머지된 PR 20건은 STATUS를 고치지 않았다. (c) wave/5 작업 4건(PR #117·#118·#121·#128)은 wave 파일 체크리스트 줄 없이 머지됐고, PR #128 본문의 `needs-judge` 질문은 라벨 없이 남았다.

## 결정
1. **입학 전 선택은 분야 하나다. 학교·학과·세부전공·자금 경로·지도교수 유형 선호와 과제 참여율은 운이다.** 0005의 나머지(결정 지점 7종, 선택은 확률만 바꾼다는 원칙, 확률 힌트, 분기와 동기 4명)는 그대로다. 플레이어의 시간 선택(월 포커스, 아르바이트·강의 시간, 선택권 §4.7)도 그대로다. 엔진 `createLife`는 여섯 단계 설정을 그대로 받으므로 단계를 다시 열 때는 화면만 바꾼다. 0005 상태 줄에 이 기록을 적는다. Wave 6 선택 민감도 측정(wave-06 체크리스트 2번)은 이 범위의 선택만 잰다.
2. **실명은 화면뿐 아니라 저장소 기록 전체에서 금지 대상이며, 학술지·학회를 포함한다.** #113 실행 전까지 새로 쓰는 모든 텍스트는 id나 가상 표시명을 쓴다. 화면의 투고처는 등급(T1~T4 ↔ Q1~Q4)과 종류(학술지·학회)로만 보인다. 0004의 "데이터 팩은 실명" 부분은 #113 실행 때 비공개 대응표 방식으로 바뀐다. 0004 상태 줄에 이 기록을 적는다.
3. **`git filter-repo`를 돌리기 전에 인용 해시 보존 방법을 fable이 판정해 결정 기록으로 남긴다.** 이 기록은 방법을 정하지 않는다. 선택지는 적어도 (a) 옛 해시 → 새 해시 대응표를 저장소에 커밋하고 인용은 그대로 둔다, (b) 실행 전에 모든 해시 인용을 PR 번호와 파일 경로로 바꾼다, (c) 새 저장소로 옮기고 옛 저장소를 읽기 전용으로 남긴다이다. 실행 시점과 공개 범위(같은 저장소 강제 푸시 또는 새 저장소)는 #113 본문대로 사용자가 정하고, 실행은 사용자 확인 뒤 main thread가 한다.
4. **공유 파일은 그 파일을 바꾸게 만든 PR이 같은 PR에서 고친다.** (a) 0014에 행을 더하거나 엔진 주석에 새 0014 번호를 쓰는 PR은 같은 PR에서 `scripts/check-assumed.mjs`가 exit 0인지 확인하고 출력 두 줄(missing, out-of-range)을 PR 본문에 붙인다. 이 스크립트는 test 워크플로우에 넣는다(Wave 6 이관). (b) wave/N issue를 닫는 PR은 STATUS의 해당 wave 행과 wave 파일 체크리스트 줄을 같은 PR에서 고친다. design 큐 PR(`[design]` issue)은 STATUS를 고치지 않는다. 충돌을 피하려고 고치지 못했으면 PR 본문에 "STATUS 미갱신"을 적고, 다음에 머지되는 wave/N PR이 고친다. (c) issue 없이 사용자 규칙만으로 여는 PR은 issue를 먼저 만들거나, 같은 PR에서 wave 파일 체크리스트 줄을 더한다. (d) PR 본문에서 판정을 묻는 질문은 `needs-judge` 라벨을 붙인 issue로 옮긴 뒤에만 PR을 머지한다.

## 결과
얻는 것: 0005·0004를 읽는 사람이 Wave 5의 범위 변경을 한 곳에서 찾는다. Wave 6 선택 민감도 측정의 대상이 정해진다. #113 실행이 0016 §1의 해시 인용 규칙을 말없이 깨뜨리지 않는다. `check-assumed`와 STATUS가 회고 전에 어긋나는 일이 줄어든다. 영향 받는 파일: `docs/workflow.md` §브랜치·PR 규약 세 줄(§4), `docs/design/decisions/0004-*.md`·`0005-*.md` 상태 줄, `docs/waves/wave-06-balance-retro.md` §Wave 5 회고에서 이관, `docs/prompts/weaver-retro-any.md`·`narrative-collector-wave2.md` 자기 검증 줄. 영향 받는 레코드 id: 없음.

잃는 것: 플레이어가 고를 수 있는 것이 줄어 "선택이 결과를 바꾼다"(0005)는 체감이 결정 지점과 월 포커스에만 남는다. #113 실행 전에 판정 한 번이 더 든다. PR마다 STATUS·체크리스트·검사 출력을 챙겨야 해서 작은 PR도 손이 더 간다.

다시 볼 조건: Wave 6 플레이테스트에서 "고를 것이 없다"는 피드백이 나오면 입학 전 선택 단계를 다시 연다(화면만 바꾸면 된다). #113 판정이 (c) 새 저장소를 고르면 0016 §1의 병합 방식 규칙을 새 저장소에 그대로 옮길지 다시 본다. STATUS 충돌이 계속되면 STATUS를 PR이 아니라 회고·wave 시작 PR만 고치는 방식으로 바꾼다.

### 반대 근거
- (1) 0005를 "대체됨"으로 바꾸고 새 기록에 선택 범위 전체를 다시 쓰면 정본이 하나가 된다. 그러나 0005의 대부분(결정 지점, 확률 원칙, 분기)은 그대로라 대체하면 그 부분을 옮겨 써야 하고, 엔진은 여전히 6단계 설정을 받는다. 그래서 상태 줄에 일부 보완을 적는 쪽을 택한다.
- (2) 0004를 바로 "대체됨"으로 바꾸는 선택지가 있다. 그러나 #113 실행 전까지 데이터 팩은 실제로 실명을 담고 있고, 0004의 화면 치환 함수는 그대로 쓰인다. 실행 뒤에 대체한다.
- (3) 판정 없이 #113 절차대로 바로 실행하면 일정이 빠르다. 그러나 해시 인용이 깨지면 Wave 1~5 체크리스트의 완료 근거를 다시 찾을 수 없고, 되돌릴 수 없는 강제 푸시 뒤에는 고칠 방법이 대응표밖에 없다. 판정 비용이 작다.
- (4) 공유 파일을 한 세션(예: 회고 세션)만 고치게 하면 충돌이 없다. 그러나 그러면 Wave 5처럼 회고 전까지 어긋남이 쌓인다. `check-assumed`는 CI에 넣으면 사람이 챙길 필요가 없다는 반론이 맞고, 그래서 (a)에 CI 편입을 함께 둔다. PR 본문의 판정 질문을 머지 조건으로 두면 작은 PR이 판정을 기다리느라 늦어질 수 있다. 그래도 PR #128처럼 질문이 묻히는 쪽보다 낫다.
