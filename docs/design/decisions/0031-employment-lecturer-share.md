## 결정
**채택 R1a 한 가지: 0014 #106의 레코드 부분(L_k)만 보정한다.** 비전임(명예 제외) 스톡에 강사 비중을 곱해 강사 아닌 비전임(겸임·기타)을 뺀다. 계수 0.15와 경계 0.20·0.85는 그대로다.

```
s_강사 = statistics-faculty-lecturers-all-2025 ÷ (statistics-faculty-nonfulltime-stock-all-2025 − statistics-faculty-honorary-all-2025)
       = 40,180 ÷ (99,185 − 22,124) = 40,180 ÷ 77,061 = 0.5214
L_k   = (비전임_k − 명예 배분_k) × s_강사 ÷ 학위 취득자_k
h_k   = clamp(0.15 × L_k, 0.20, 0.85)
```

입력: 비전임_k `statistics-faculty-nonfulltime-stock-{humanities 17,279, social 14,589, natural 8,840, engineering 15,259}-2025`, 명예 배분_k = 22,124 × `statistics-faculty-fulltime-stock-{k}-2025` ÷ `statistics-faculty-fulltime-stock-all-2025` 64,672 = 2,893.4 / 3,408.3 / 2,482.9 / 4,961.1(#105 그대로), 학위 취득자_k `statistics-phd-awarded-{humanities 1,898, social 3,694, natural 2,912, engineering 5,171}-2025`. 결과 L_k 3.952 / 1.578 / 1.138 / 1.038, 0.15 × L_k 0.5928 / 0.2367 / 0.1707 / 0.1558, **h = 0.593 / 0.237 / 0.20(하한) / 0.20(하한)**(이전 0.850(상한) / 0.454 / 0.327 / 0.299).

구현: `engine/src/career/labor.ts`의 `lecturerShare`(새 함수)와 `lecturerH`, `engine/src/data/statistics.ts`의 `facultyMarket`이 두 레코드(`statistics-faculty-lecturers-all-2025`, `statistics-faculty-nonfulltime-stock-all-2025`)를 읽는다. 계수를 0.0782로 두어도 수치는 같지만 레코드 부분과 가정 부분을 가르기 위해 L_k 정의에 넣었다. 설계 가정 하나: 계열별 강사 분해가 없어 s_강사를 전 계열 공통으로 둔다. 0014 #106 값·사유 칸을 2026-10-23으로 고쳤다(새 행 없음, 142행).

**#107·#110·#111·#112는 이 단계에서 바꾸지 않는다**(값 칸에 "2026-10-23 2단계: 정의 판정 전 보류" 한 문장). 이 단계의 적합값(fitted)은 0개다. 채택하지 않은 적합값(0021 명시용): B의 #106 {lo 0.10, hi 0.20}(= 전 계열 강사 h 0.20 상수), #107 인문사회 0.08, #110 인문사회 0.04, #111 인문사회 0.03(행 분할 필요), #112 이공 0.40·인문사회 0.10, 그리고 C의 더 낮은 값들 — 모두 "목표에 맞춘 값"이다.

### 판정 근거
- (1) **#106 보정은 레코드 유도다.** 노동 §3.1이 이미 "비전임(명예 제외)에는 강사 외에 겸임·초빙·기타가 남아 있다 … 공학의 비전임에는 산업체 겸임이 많아 실제 강사 수요보다 크게 잡힐 수 있다"고 적었고, #106 사유는 "비전임(명예 제외) ÷ 학위 취득자의 상대 크기"다. 게임의 `lecturer` 경로는 시간강사이고, `statistics-faculty-lecturers-all-2025` note가 2020년부터 강사가 비전임교원으로 분류되고 종전 시간강사를 포함한다고 적어 강사 스톡이 맞는 분자다. 전체 수준 항등식(강사 40,180 + 겸임 10,567 + 명예 22,124 + 기타 26,314 = 99,185)에서 s_강사 0.5214가 나온다. 출처 근거 + 설계 가정(계열 공통).
- (2) **A·A2 기각(#112 변경 보류).** "취업률 × 상용 비율(또는 × 정규직 비율) = 기업 연 채용 확률"이라는 대응은 레코드가 아니라 설계 가정이고, 레코드 정의의 창(+0)에서는 (P) 위험률로도 ict 0.472·engineering 0.468이 하한 0.582·0.525 아래라 이공 기업·박사후 위험률을 내리는 변경은 정의 판정 뒤 되돌려야 할 가능성이 크다(A2를 +3 창에서 재면 ict 0.556·engineering 0.491로 둘 다 실패). 정의가 정해지기 전의 #112 변경은 방향조차 정해지지 않은 양을 맞추는 일이다.
- (3) **B·C 기각.** 0029 재판정의 2단계 조건 1~5는 글자대로 충족하지만, (a) 맞추는 모의 양(졸업 + 12개월 안 첫 채용)이 기준 레코드의 양(취득 시점 재직·확정)과 달라 적합값의 크기에 근거가 없다 — 0021 "레코드가 없는 상수를 … 레코드가 없는 숫자에 맞추는 것은 보정이 아니다"와 같은 종류다(0.408은 레코드지만 비교되는 모의 양이 그 숫자의 정의가 아니다). (b) #106 hi 0.20(B)·0.12(C)는 네 계열(옛 0.15 × L_k = 1.14 / 0.454 / 0.327 / 0.299)을 모두 한 상수로 잘라 레코드 유도 L_k(옛 7.6 / 3.0 / 2.2 / 2.0)가 아무 일도 하지 않게 되어 행의 사유와 어긋난다. (c) C의 임시(강사+박사후) 비율 0.39 / 0.56 / 0.35(사회/경영법/예인문)는 레코드 역산 약 0.51 / 0.45 / 0.52와 어긋난다(B는 0.46 / 0.59 / 0.45로 가깝다 — B의 반대 근거는 (a)(b)와 경계 칸이다).
