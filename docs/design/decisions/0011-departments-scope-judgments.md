# 0011. 모집 단위 범위 483개와 NRF 코드 판정

## 상태
승인됨 · 2026-10-13 (issue #5, 판정자 fable/main thread; PR 머지로 확정)

## 맥락
수집자(sonnet 1 + 보조 5)가 20개교의 2027학년도 전기 박사 모집요강에서 모집 단위 483개를 읽었다. 어쩌다 박사 v3.5의 241개 중 240개를 확인했고(GIST 수리과학과는 석사만 모집), 243개를 추가했다. 추가분 중 137개는 트랙이 분명하고(통계·영어영문·언어·경제·행정·재료·반도체 등) 106개는 수집자가 트랙을 판단했다. 쟁점: (1) 241로 자를지 483을 쓸지. (2) 학과명이 트랙 primary와 다른 NRF 중분류에 속하는 40건(항공우주·조선·자동차·원자력·의공학·건축·전자/정보통신·정책학·영어학·고분자·생화학)의 NRF 코드. (3) 같은 학과가 두 트랙에 걸치는 경우. (4) 협동과정의 종류 값.

## 결정
- **범위 483개 전부.** 선택 단위를 학과까지 내리는 것이 이 게임의 요구(결정 기록 0005)이므로 출처가 있는 단위는 모두 둔다. 106개 수집자 판단 단위는 note에 "수집자 메모"로 이유를 남기고 Wave 5에서 선택지로 노출할 때 재검토한다.
- **NRF 코드는 학과명을 따른다.** 40건은 트랙 primary 대신 학과명에 맞는 NRF 코드(예: 항공우주공학과 → D040000 항공우주공학, 첨단원자력공학부 → D180000 원자력공학, 의공학 계열 → D250000 의공학)를 쓴다. 트랙은 가장 가까운 게임 트랙으로 둔다. 트랙은 서사·방법 태그이고 NRF 코드가 분류 축이기 때문이다(결정 기록 0007·0008).
- **두 트랙에 걸친 학과.** 단위를 트랙마다 하나씩 두고 note에 `same_unit_as`를 적는다(영어영문학과 → english_literature + linguistics; 전기전자컴퓨터공학과 → computer + electrical 등). 엔진은 같은 학과를 두 번 세지 않도록 `same_unit_as`로 묶는다(Wave 3).
- **협동과정.** 종류 값은 `학과` 또는 `전공`으로 두고 note에 협동과정임을 적는다. 종류 enum 확장은 하지 않는다.
- **slug.** v3.5 단위는 기존 slug, 추가 단위는 `<track>-2`, `-3`. 의미 있는 slug(aerospace, naval 등)로의 변경은 Wave 4에서 엔진 키를 정할 때 한 번에 한다.
- **이번 차수 미모집 3건**(부산 심리학과 특차 ×, 경북 기계공학과·철학과 1차 ×)은 단위 존재만 확인되어 `indexed`.
- **학과별 등록금.** 학교 기본값과 다른 7건만 레코드(서울대 3, 충남대 4). schools 팩(#4) 머지 후 기본값이 바뀌면 재확인.

## 결과
얻는 것: 입학 전 선택 화면의 학과 목록이 실제 모집 단위와 일치하고(483개), NRF 코드가 학과 실체에 맞아 저널·통계와 정확히 이어짐. 잃는 것: 선택지가 많아 UI에서 계열·전공군 단계 필터가 필요; 106건은 재검토 부담. 다시 볼 조건: 부산대 전기 모집요강(11월) 공고, KAIST 2차 요강, Wave 5 선택지 노출 테스트.
