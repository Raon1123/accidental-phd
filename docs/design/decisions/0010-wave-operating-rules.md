# 0010. Wave 운영 규칙 보완 (Wave 1 회고 반영)

## 상태
승인됨 · 2026-10-13 (Wave 1 회고 §결정 기록으로 올릴 것 5건)

## 맥락
Wave 1 회고가 운영 규약의 빈칸 다섯 가지를 드러냈다. (1) 의존 관계가 있는 issue를 worktree 하나·PR 하나로 묶은 것이 "issue 1건 = 세션 1개 = worktree 1개 = PR 1개" 규약과 어긋남. (2) Wave 0 PR 머지 전에 Wave 1을 시작함. (3) 결정 기록을 "제안됨" 없이 판정자가 바로 "승인됨"으로 씀. (4) registry 포털 항목과 하위 id 규칙이 note에만 있음. (5) 모델 표의 haiku 정형화·검증 행이 쓰이지 않음.

## 결정
1. **묶음 예외.** 같은 wave 안에서 앞 issue의 산출물 없이는 시작할 수 없는 issue들(예: 분류 코드 → 매핑)은 worktree 하나·PR 하나로 묶을 수 있다. 조건: 각 issue에 claim·handoff 댓글을 따로 남기고, PR 본문에 `Closes`를 issue마다 적는다. Wave 2 통계·서사 수집은 서로 독립이므로 1:1:1 규약을 그대로 지킨다.
2. **진입 조건 완화.** 이전 wave PR이 "CI 통과 + 리뷰 완료" 상태면 다음 wave를 그 PR 브랜치에서 분기해 시작할 수 있다. 분기 사실을 claim 댓글에 적고, 머지 후 main 위로 rebase하거나 merge-base가 보존되면 그대로 둔다.
3. **결정 기록 상태.** 판정자가 쓴 기록은 "제안됨"이다. "승인됨"은 (a) 사용자가 채팅이나 PR 댓글로 승인했거나 (b) 결정 기록이 포함된 PR이 머지된 시점에 바꾼다. 0007~0009는 PR #21 머지로 승인된 것으로 본다. 판정자는 앞으로 "반대 근거" 절을 생략하지 않는다.
4. **포털·하위 id 규칙.** registry의 `-portal` 항목은 출처 계급의 입구이며 레코드의 `source_id`로 쓸 수 없다. 검증기가 이를 강제한다(`source_id`가 `-portal`로 끝나면 실패). 수치는 실제로 읽은 문서마다 `<publisher>-<year>-<topic>` 항목으로 등록한다.
5. **haiku 행 유지.** 정형화·검증 역할은 ChatGPT 경로(Luna, 사람이 붙여넣는 출력)에서 필요하므로 모델 표에 남긴다. Claude 경로에서는 `npm run validate`가 그 역할을 대신하며, 수집 agent가 직접 실행한다.

## 결과
얻는 것: 규약과 실제 운영이 일치, 포털 오용을 기계가 막음, 결정 기록 승인 주체가 분명해짐. 잃는 것: 묶음 예외로 PR이 커질 수 있음(Wave 1 PR #21이 그 예). 다시 볼 조건: Wave 2 회고에서 묶음 PR의 리뷰 부담이 문제로 드러날 때.
