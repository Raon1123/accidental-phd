# 0027. 조교 상태에서의 funding-expiry B: `already-ta`로 닫는다

## 상태
제안됨 · 2026-10-16 (issue #175, 결정 기록 0026 "다시 볼 조건" (1)의 후속이자 0023 (2) B("모든 경로·원인에서 열린다")의 일부 수정. 판정자 fable, 0026 구현·보정 8단계 맥락 없는 별도 agent, 결정 기록 0015 §3. 판정은 브랜치 `wave-6/already-ta`(= origin/main 53d14d0; 엔진의 모의실험 동작은 8단계 (ii)의 14603e3과 같다 — 그 사이 #172·#173 머지가 바꾼 엔진 코드는 결정 로그 tag 하나(`decide.ts`)와 `browser.ts` export 하나뿐이다. 결정 기록 0024·0025·0026과 0014 #45 M̄ 0.279 재유도 포함 — M̄는 자동 진행 정책에서 g 외 배수들의 기댓값(선택권 §4.2), 엔진 입력 상수는 `G_MBAR_INIT`, 결과표의 "실현 M̄"는 모의실험에서 잰 값) 위에서 코드 읽기와 저장소 밖 작업 사본의 일회성 실행(같은 seed `cal0`–`cal999`, N=1000)으로 했고, 반영은 같은 브랜치에서 했다. 판정 초안의 번호(결정 기록 0027, 0014 #142, 보정 9단계 문서)는 반영 때의 마지막 번호와 같아 그대로 썼다. 전후 측정은 [calibration-wave6-step9.md](../../oracle/calibration-wave6-step9.md)이고, (R1) 행은 반영 커밋 위에서 다시 재 판정 때 값과 같음을 확인했다. 재분배는 반영 지시에 따라 R1(정책 가중치 그대로, 재정규화)을 채택했고 R2(B 몫을 C에)는 측정한 대안으로 남긴다. 분류(0023 (3)의 규칙 변경인가, issue #175 본문의 정책 변경인가)는 열린 판정 질문이며 보고는 0023 (3)의 이름("정책 고정 + 규칙 변경")으로 한다(아래 "판정 질문"). 화면 문자열 `play.unavailable.already-ta`는 엔진 커밋이 판정 초안의 제안 문구로 한 키만 함께 넣었고(web 사유 문구 시험 때문), 이후 문구는 design 세션 몫이다.)

## 맥락
약어·용어: 조교(TA, teaching assistant)는 결정 기록 0022·0026과 같이 학교 레코드 `schools-{school}-all-stipend-ta*`의 교육·연구조교다. "조교 상태"는 0014 #140의 술어 `fundingState.dutyHours > 0`(경로 `self`, 의무 10시간, 기한 없음 `until −1`)이다. "위기 결정"은 선택권 스펙 §5.5의 재정 위기(일반 대출 한도 도달 + 현금 음수 3개월)가 강제로 여는 `funding-expiry` 결정 지점이다. PR은 pull request(브랜치 병합 요청)다.

쟁점: 결정 기록 0026이 B(조교·강의 근로 전환)와 입학 때 조교 추첨을 같은 조교 상태로 묶은 뒤, 이미 조교 상태인 삶의 위기 결정에서 B는 지금과 같은 상태를 다시 주고(`taFundingState(data, school)` → 같은 값) C(버틴다)는 조교 상태를 유지한다(0014 #141). 둘 다 `fundingState`를 바꾸지 않는다. 결정 기록 0005의 독해("고를 수 있는 선택지는 실제로 수행 가능한 행동이어야 한다", 0023 (1)이 설계 가정으로 명시한 읽기)에 따라 B를 새 사유 `already-ta`로 닫을지, B에 다른 뜻을 줄지, 그대로 둘지 정한다. 닫는다면 자동 정책(0014 #46)이 B의 가중치를 어떻게 다시 나누는지도 정한다.

## 결정
네 쟁점에 하나씩 판정한다.

(1) **스펙·구현 불일치가 아니라 §3.3의 설계 빈칸이다. 0023 (2) B의 "모든 경로·원인에서 열린다"를 조교 상태에 한해 바꾼다.** §3.3 B에는 가용 조건 문장이 없고 코드는 그 문장대로이므로 0016 §2 차이 감사 행을 채울 수 없다(0023 (1)·0025 (2)와 같은 종류). 0026이 그 수정을 이 판정에 넘겼으므로, 0023 본문은 고치지 않고 0023 "상태" 줄에 이 기록을 가리키는 문장을 더한다(0005 → 0018의 선례).

(2) **조교 상태(`fundingState.dutyHours > 0`, 0014 #140 술어)에서는 B를 새 사유 `already-ta`로 닫는다.** 근거는 선례의 종류다: 조교 상태의 B는 `taFundingState(data, school)`가 지금 상태와 같은 값을 돌려주는 **항등 효과**이고(기존 시험 396~407행 `toEqual(ta)`), `no-funding`이 닫는 자비 삶의 A(성공 `s` 그대로, 실패는 `fundingExpired`가 무시)와 같은 "할 것이 없다"는 사유다. 효용 비교(0023 (2)가 금한 "조교 월액 ≥ 장려금")가 아니라 상태 비교이고, 새 상수는 없다. 술어를 `route === 'self' && dutyHours > 0`이 아니라 `dutyHours > 0`으로 두는 것은 #140이 조교 판정 술어를 그렇게 정했기 때문이다(조교가 아닌 상태는 모두 `dutyHours 0`). B에 다른 뜻을 주지 않는다: (a) "조교 시간 변경·추가"는 조교 근무 시간·지급 학기 레코드가 없어(0026 "다시 볼 조건" (2)·(3)) 레코드 없는 새 상수가 되고, §3.3 B·#140이 조교 상태를 하나로 정했다. (b) 설명문만 "조교 유지"로 바꾸면 C와 효과·설명이 같은 선택지 둘이 남아 지금보다 나쁘다. 그대로 두지도 않는다: 이미 조교인 플레이어에게 "조교로 전환"이 열려 있고 그 효과가 아무것도 아니며, 정책 가중치 0.6이 그 무효 선택지로 간다. "다른 선택 보기"(0005)에서 B와 C 분기가 같은 생애가 된다. 0014 새 행 #142.

(3) **정책 가중치는 바꾸지 않는다. B가 닫힌 뒤의 재분배는 `policy.ts`가 이미 하는 재정규화에 맡긴다(R1).** 조교 상태의 위기 결정은 A·B가 닫혀 C 0.5 / D 0.5가 되고, D가 `leave-cap`이면 C 1.0이다. B의 몫을 C에 접어 넣어 행동 분포(유지 0.8 / 휴학 0.2)를 보존하는 안(R2)은 #46을 맥락에 따라 고치는 것이라 0016 §3 (b)의 정책 변경이고, 측정에서 기준선과 모든 칸이 같다([9단계](../../oracle/calibration-wave6-step9.md) §2 표: B≡C라 같은 난수가 같은 결과를 낸다). R1은 86건 중 30건을 유지에서 휴학으로 옮기지만 결과표의 통과 칸·재정 파탄·졸업·학위 기간·M̄가 움직이지 않는다. 분류: 0023 (3)대로 **규칙 변경(정책 고정)**이다 — 가용 조건이 정책 분포를 간접으로 바꾸는 것은 `leave-cap`·`no-funding`·`not-expiring`의 기제와 같다. issue 본문의 "정책 변경으로 따로 보고"는 0023 (3)과 어긋나므로 이 기록은 0016 §3 (d) 보고를 "정책 고정 + 규칙 변경"(R1) 행과 "정책 변경 대안"(R2) 행으로 나눠 적고, 분류 자체는 사용자 판정 항목으로 올린다(아래 "판정 질문").

(4) **보정 손잡이가 아니다.** 조교 상태의 위기는 월 순현금이 구조적으로 음수라(조교 월액 30~55만 + 근로 대 생활비, 0024 판정 근거 (4)) 어느 선택지도 3개월 안에 현금을 0 위로 올리지 못한다: 기준선에서 B 88%·C 100%·D 85%가 `financial`, R1에서 C 92%·D 90%. 그래서 이 변경은 정직성(선택지 수준, 0023 (4) "정직성은 종료 규칙이 아니라 선택지 수준에서 지킨다")의 일이지 0021 조건의 손잡이가 아니다. 실현 M̄가 움직이지 않으므로(0.276 → 0.276) 0015 §4 재유도는 없다.

## 결과
얻는 것: 조교 상태의 위기 결정 메뉴가 "버틴다(C) / 휴학하고 일한다(D)" 둘이 되어 모든 열린 선택지가 실제 행동이다(0005·0023 (1)). "조교로 전환"이 이미 조교인 삶에 보이지 않는다. "다른 선택 보기"의 분기가 서로 다르다. 자동 정책이 무효 선택지에 0.6을 보내지 않는다. 새 상수·새 레코드 인용 없음, #46 그대로.

측정([9단계](../../oracle/calibration-wave6-step9.md), 기준선 = 8단계 (ii)와 같은 엔진 동작의 origin/main 53d14d0, N=1000 같은 seed; (R1)은 반영 커밋 위에서 다시 잼): (R1) 재정 파탄 19.5% (195) → 19.5% (195), 졸업 60.7% → 60.7%, 0021 조건값 0.047 / 0.040 / 0.042 / 0.027 → 0.046 / 0.040 / 0.042 / 0.027(0/4 그대로), 통과 칸 학위 기간 2/4 · 휴학 3/4 · 이탈 2/4 · 취업 3/6 · 수요 14/14 그대로, 실현 M̄ 0.276 그대로. 조교 상태 위기 결정 86건이 B 49 / C 17 / D 20 → C 36 / D 50. (R2)는 (0)과 모든 칸이 같다.

잃는 것: 조교 삶의 자동 정책 위기 분포가 유지 0.8 / 휴학 0.2에서 0.5 / 0.5로 옮겨 자발 휴학 시작률이 0.073 → 0.078/년, 휴학 비율 스냅샷이 +0.001~+0.003 오른다(자연 0.115 → 0.118, 상한 0.105 위에서 실패가 굳는다; 통과 칸 수는 3/4 그대로). 새 사유 코드와 화면 문구가 필요하다. web 시험(`web/test/play.test.ts`의 사유 문구 검사)이 엔진의 사유 문자열 전부에 문구를 요구하므로 엔진 커밋이 `strings.ko.ts`의 한 키를 제안 문구로 함께 넣었다(web 시험 자체는 고치지 않았다).

다시 볼 조건: (1) 조교 근무 조건 레코드(주당 시간 분포, 추가 조교 가능 여부, 최대 지급 학기)가 들어오면 B에 "조교 시간 조정" 같은 다른 뜻을 줄 수 있는지 다시 본다(그때 `already-ta`는 "조정할 것이 없다"로 좁아진다). (2) 플레이테스트에서 조교 삶의 위기 결정이 "C든 D든 끝난다"로 읽히면 그것은 #62(0024)·#36의 항목이지 이 기록의 항목이 아니다. (3) 사람 플레이어의 위기 결정 로그가 쌓여 R1(0.5/0.5)과 분포가 크게 다르면 R2 또는 새 가중치를 0016 §3 (b) 절차로 판정한다.

영향 받는 레코드 id(값은 바뀌지 않는다, 인용만): `schools-{school}-all-stipend-ta*` 12건(B 월액), `statistics-phd-leave-rate-{humanities,social,natural,engineering}`, `statistics-phd-dropout-rate-{…}`, `statistics-phd-duration-mean-years-{…}`. 영향 받는 0014 행: 새 행 #142; #140 "쓰이는 곳"에 `optionUnavailable` 추가; #46 값 변경 없음. 영향 받는 파일: `engine/src/decide.ts`, `engine/src/assumed.ts`(주석 1줄), 시험 3종(`decide`·`advanceMonth`·`policy`), 선택권 스펙 §3.3·§4.4·§5.5, `docs/design/decisions/0014-assumed-probabilities.md`, `0023` 상태 줄, `0026` 상태 줄, `README.md`, `docs/oracle/calibration-wave6-step9.md`(신규), `docs/waves/wave-06-balance-retro.md` 순서 3 줄, `web/src/strings.ko.ts`(한 키, 제안 문구; 이후 문구는 design 세션).

### 반대 근거
- **그대로 두자(0023 (2) B 유지):** 모든 경로에서 열린 B가 규칙이 단순하고, 조교 삶에서 B를 골라도 해가 없다(상태 불변). 그러나 "해가 없다"는 선택지는 0023이 `not-expiring`으로 닫은 살아 있는 자금의 A와 같은 종류다 — 그 A도 과제 자금에서는 기한을 옮기는 성공 분기가 있었는데 현금을 바꾸지 않는다는 이유로 닫혔고, 조교 상태의 B는 어느 분기도 없다. 플레이어 화면에 "조교로 전환"이 이미 조교인 삶에 뜨는 것은 설명문과 효과가 어긋나는 0023 (1) (a)와 같은 결함이다.
- **B에 "조교 유지"라는 뜻을 주자(0026 다시 볼 조건의 괄호 안):** 문구만 바꾸면 코드 변경이 없다. 그러나 C가 이미 조교 상태를 유지하므로(#141) 효과도 설명도 같은 선택지가 둘 남고, 자동 정책 0.6 / 0.2가 같은 행동에 두 번 걸린다.
- **B에 "조교 시간 추가·조정"을 주자:** 현실에서 조교는 과목 수·시간을 늘릴 수 있고 수입을 올리는 실제 행동이다. 그러나 추가 조교의 월액·시간·상한 레코드가 없어(0026 (2)·(3)) 새 상수가 둘 이상 필요하고, 0014 #140이 조교 상태를 한 값으로 정했다. 레코드가 들어오면 다시 본다(다시 볼 조건 (1)).
- **R2(행동 분포 보존)를 택하자:** 결과표를 바꾸지 않고 자동 정책의 "유지 0.8 / 휴학 0.2"가 보존된다. 0.5 / 0.5는 아무 레코드도 없는 분포이고 0.8 / 0.2도 마찬가지이지만 후자는 적어도 지금까지의 측정과 이어진다. 그러나 (a) R1의 결과 칸도 바뀌지 않아 "보존"으로 얻는 것이 결과표에는 없고, (b) R2는 #46을 "B가 닫히면 C에 더한다"는 조건부 규칙으로 만드는 정책 변경이라 0016 §3 (b) 판정이 따로 필요하며, (c) `leave-cap`·`no-funding`·`not-expiring`은 모두 재정규화에 맡겼으므로 `already-ta`만 다르게 두면 사유마다 재분배 규칙이 생긴다. 사람 플레이어의 분포가 쌓이면 다시 본다(다시 볼 조건 (3)).
- **술어를 `taFundingState(data, school)`와의 동치로 두자(항등 효과를 직접 검사):** 뜻은 더 정확하다. 그러나 `optionUnavailable`은 `data`를 받지 않고(시그니처 변경이 `policy.ts`·`describeOptions`·시험에 번진다), 조교 상태가 그 값과 다를 수 있는 경로가 엔진에 없다(`taFundingState`만 `dutyHours`를 0 아닌 값으로 쓴다, #140). #140 술어를 쓰는 것이 0026과 한 규칙이다.
- **분류 반대 — "정책 변경으로 보고하라"(issue #175 본문):** 가용 조건이 정책 분포를 0.6 / 0.2 / 0.2 → 0 / 0.5 / 0.5로 바꾸므로 정책이 바뀐 것과 같다는 읽기다. 그러나 0023 (3)이 같은 상황을 규칙 변경으로 분류했고 그 결정은 PR #165 머지로 승인됐다. 이 기록은 0023의 분류를 따르되 9단계 §2 표에 두 행을 모두 적어 보고 형식에서는 어느 쪽 읽기도 손해가 없게 했다. 어느 분류를 기록할지는 사용자 판정 항목이다.

### 판정 질문 (사용자)과 반영
1. **분류 — 열린 질문.** 재분배는 반영 지시에 따라 R1(가중치 불변, 재정규화 C 0.5 / D 0.5)을 기록했다. R2(B 몫을 C에, 유지 0.8 / 휴학 0.2 보존)는 9단계 §2에 측정한 대안 행으로 남는다. 측정은 둘 다 결과 칸을 움직이지 않는다. 남은 질문: 이 재분배를 0023 (3)대로 "규칙 변경(정책 고정)"으로 기록하는가, issue #175 본문대로 "정책 변경"으로 기록하는가. 이 기록·0014 #142·9단계 문서는 0023 (3)의 이름으로 보고했고, 9단계 §2 표가 두 행을 모두 적어 어느 분류를 고르든 보고 형식은 바뀌지 않는다.
2. **0023 상태 줄 수정.** 반영 지시에 따라 0023 (2) B "모든 경로·원인에서 열린다"의 본문은 두고 상태 줄에 0027 포인터만 더했다(0005 → 0018 선례). 0026도 상태 줄에 포인터만 더했다.
3. **머지 순서.** 반영 지시에 따라 엔진 커밋이 `strings.ko.ts`의 `already-ta` 한 키를 제안 문구("이미 조교로 일하고 있어 전환할 것이 없습니다.")로 함께 넣었다. 이후 문구는 design 세션이 정한다. `web/` 안의 다른 변경은 없다.
4. **§4.4 문장 추가.** 반영 지시에 따라 넣었다: 스펙 §4.4에 "고를 수 없는 선택지는 가중치 0으로 두고 다시 정규화한다"가 적혀 0023 (3)의 기제가 스펙 본문에 올라갔다. 1번의 분류 질문은 이 문장으로 정해지지 않는다(문장은 기제를 적을 뿐 규칙 변경인지 정책 변경인지 이름 붙이지 않는다).
